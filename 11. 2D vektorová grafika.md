## Počítačová grafika

V **rastrové grafice** zpracovávané a zobrazované informace popisujeme a ukládáme *diskrétně* ve formě **rastrové matice** (2D/3D). Jeden prvek této matice je **pixel**. Obraz získáme *manuálně* (malováním), *syntézou* (generováním, převodem) nebo *snímáním* (kamerou).

Ve **vektorové grafice** zpracovávané a zobrazované informace popisujeme a ukládáme analyticky ve formě **skupiny vektorových entit**: úsečky, kružnice, křivky, polygony atd. Tento popis získáme *manuálně* (kreslením) nebo *syntézou*.

Popis dat může být vektorový nebo rastrový, ale **většina současných zobrazovacích zařízení je rastrová**. Naše vidění (oko) je rastrové, naše vnímání (mozek) je vektorové.

## Rasterizace

**Rasterizace** je proces převodu *vektorové reprezentace dat* na jejich *rastrovou formu* s cílem dosáhnout maximální možné kvality a zároveň rychlosti výsledného zobrazení. Realizuje se v hardwaru **grafické karty**.

### Rasterizace úsečky

**Obecná rovnice úsečky**: $$Ax + By + C = 0, \quad A = (y_1 - y_2), \quad B = (x_2 - x_1)$$

> [!note]
> $A$ a $B$ jsou souřadnice **normálového vektoru** úsečky/přímky (kolmého na úsečku/přímku), proto je jejich pořadí naopak oproti směrovému vektoru (souřadnice $y$ normálového vektoru je rovna souřadnici $x$ směrového vektoru a naopak) a jedna z nich má otočené znaménko ($y_1 - y_2$). Normálový vektor může být i jiný.

**Parametrické vyjádření úsečky**: $$x = x_1 + t(x_2 - x_1), \quad y = y_1 + t(y_2 - y_1), \quad t \in \langle 0, 1 \rangle$$

Všechny následující algoritmy jsou odvozeny pro **případ, kdy**

- úsečka leží *v prvním kvadrantu*,
- *je rostoucí* od počátečního bodu $P_1$ ke koncovému $P_2$ a
- nejrychleji roste ve *směru osy X*.

Ostatní polohy úsečky je potřeba **převést na tento případ** prohozením souřadnic, prohozením os apod.

#### Algoritmus DDA

**Digital differential analyser** (*DDA*) je jeden z prvních algoritmů rasterizace úsečky. Používá **floating-point aritmetiku**.

- *Vykreslujeme po pixelu* od bodu $P_1$ k bodu $P_2$.
- V ose X postupujeme *s přírůstkem $dx = 1$*.
- V ose Y je přírůstek dán velikostí *směrnice úsečky*.
- Souřadnice Y *se zaokrouhluje* na nejbližší celé číslo.

```c
void line_dda(int x1, int y1, int x2, int y2) {
	double k = (y2 - y1) / (x2 - x1);
	double y = y1;
	
	for (int x = x1; x <= x2; x++) {
		draw_pixel(x, round(y));
		y += k;
	}
}
```

#### Algoritmus DDA s fixed-point aritmetikou

Je **rychlejší než DDA**, protože pracuje pouze s celočíselnou aritmetikou.

```c
#define FRAC_BITS 8

void line_dda_fixed(int x1, int y1, int x2, int y2) {
	int k = ((y2 - y1) << FRAC_BITS) / (x2 - x1);
	int y = y1 << FRAC_BITS;
	
	for (int x = x1; x <= x2; x++) {
		draw_pixel(x, y >> FRAC_BITS);
		y += k;
	}
}
```

#### Midpoint (Bresenhamův) algoritmus

Bresenhamův neboli **midpoint algoritmus** je *nejčastěji používaný* algoritmus rasterizace úsečky. Používá **celočíselnou aritmetiku**, sčítání a porovnání. Efektivněji a *snadněji se implementuje* v HW.

- *Vykreslujeme po pixelu* od bodu $P_1$ k bodu $P_2$.
- V ose X postupujeme *s přírůstkem $dx = 1$*.
- O posunu v ose Y rozhodujeme podle **znaménka prediktoru**.

![[11_midpoint.png]]

**Výpočet chyby vykreslování** $E$: $$E_i + \frac{\Delta y}{\Delta x}$$

Pokud jsme **pod midpointem**, *zůstáváme* na stejné úrovni a *chyba se zvětší*.
Pokud jsme **nad midpointem**, *skočíme* o úroveň výš a *chybu otočíme* do záporu.

| Chyba                                      | Bod                  | Nová chyba                                        |
| ------------------------------------------ | -------------------- | ------------------------------------------------- |
| $E_i + \frac{\Delta y}{\Delta x} < 0.5$    | $[x_i + 1, y_i]$     | $E_{i + 1} = E_i + \frac{\Delta y}{\Delta x}$     |
| $E_i + \frac{\Delta y}{\Delta x} \geq 0.5$ | $[x_i + 1, y_i + 1]$ | $E_{i + 1} = E_i + \frac{\Delta y}{\Delta x} - 1$ |

**Převod na test znaménka**: $$P_i = 2 \Delta x E_i + 2 \Delta y - \Delta x$$

Obě nerovnice a přírůstky **násobíme $2 \Delta x$**. Nyní se o posunu na ose Y rozhoduje *porovnáním znaménka* a není potřeba floating-point výpočet.
Rozhodovací člen $P_i$ nazveme **prediktorem**.

| Prediktor    | Bod                  | Nový prediktor                              |
| ------------ | -------------------- | ------------------------------------------- |
| $P_i < 0$    | $[x_i + 1, y_i]$     | $P_{i + 1} = P_i + 2 \Delta y$              |
| $P_i \geq 0$ | $[x_i + 1, y_i + 1]$ | $P_{i + 1} = P_i + 2 \Delta y - 2 \Delta x$ |

```c
void line_midpoint(int x1, int y1, int x2, int y2) {
	int dx = x2 - x1;
	int dy = y2 - y1;
	int p = 2 * dy - dx;
	int p1 = 2 * dy;       // Pricita se kdyz p < 0
	int p2 = p1 - 2 * dx;  // Pricita se kdyz p >= 0
	
	for (int x = x1; x <= x2; x++) {
		draw_pixel(x, y);
		if (p >= 0) {
			p += p2;
			y++;
		} else {
			p += p1;
		}
	}
}
```

### Rasterizace kružnice

**Kružnice** je definovaná:

- *souřadnicemi středu*,
- hodnotou *poloměru* a
- *rovnicí kružnice* popisující geometrii.

$$(x - s_1)^2 + (y - s_2)^2 - R^2 = 0$$

Kružnice je **8× symetrická**, proto provádíme výpočet pro **1/8 bodů** v polovině prvního kvadrantu, zbylé body získáme *záměnou souřadnic*. Algoritmy jsou odvozeny **pro kružnici se středem v počátku** $[0, 0]$.

#### Vykreslování po bodech

#### Vykreslování jako n-úhelník

Varianta algoritmu [[#Algoritmus DDA|DDA]] pro kružnici. Používá **floating-point aritmetiku** a **rotační transformaci bodu**. Nízká efektivita, náročná implementace do HW.

- Rekurentně se posouváme o *konstantní přírůstek úhlu*.
- Funkce $\sin$ a $\cos$ jsou *vypočítány pouze jednou*.
- Souřadnice X a Y *se zaokrouhlují* na nejbližší celé číslo.
- Vypočtené souřadnice *spojujeme úsečkami*.

![[11_dda-kruznice.png]]

**Nové souřadnice bodu** (podle rotační matice): $$x_{n + 1} = x_n \cos \alpha - y_n \sin \alpha, \qquad y_{n + 1} = x_n \sin \alpha - y_n \cos \alpha$$

```c
void circle_dda(int r, int n) {
	double cosa = cos(2 * PI / n);
	double sina = sin(2 * PI / n);
	int x1 = r;
	int y1 = 0;
	int x2, y2;
	
	for (int i = 0; i < n; i++) {
		x2 = x1 * cosa - y1 * sina;
		y2 = x1 * sina + y1 * cosa;
		draw_line(x1, y1, x2, y2);
		x1 = x2;
		y1 = y2;
	}
}
```

#### Midpoint algoritmus

Používá stejný přístup jako [[#Midpoint (Bresenhamův) algoritmus|midpoint algoritmus pro úsečky]]. **Poloha midpointu** se určuje *vůči kružnici* (in, out).

- Vykreslujeme *po pixelu* od bodu $[0, R]$, dokud není $x = y$.
- V ose X postupujeme *s přírůstkem $dx = 1$*.
- O posunu v ose Y rozhodujeme podle **znaménka prediktoru**.

![[11_midpoint-kruznice.png]]

```c
void circle_midpoint(int s1, int s2, int r) {
	int x = 0;
	int y = r;
	int p = 1 - r;
	int x2 = 3;
	int y2 = 2 * r - 2;
	
	while (x < y) {
		draw_pixel_circle(x, y);
		
		if (p >= 0) {
			p -= y2;
			y2 -= 2;
			y--;
		}
		
		p += x2;
		x2 += 2;
		x++;
	}
}
```

## Křivky

Rovnost přímek a kulatost kružnic je ideál, který se ve skutečnosti příliš nevyskytuje, proto potřebujeme umět popsat **křivé tvary**.

### Vlastnosti křivek

- **Invariance k affiním transformacím a projekci** – rotace řídicích bodů *nemá vliv na tvar křivky*.
- **Konvexní obálka** – křivka *leží v konvexní obálce* svých řídicích bodů.
- **Interpolace krajních bodů** – křivka *prochází krajními body*.

**Interpolační křivka** přímo *prochází body* („proložení“ bodů křivkou).
**Aproximační křivka** *neprochází body* (tzv. řídicí body).

**Racionální křivka** přiřazuje *váhové koeficienty* $w_i$ řídicím bodům. **Je invariantní** vůči perspektivní projekci.

**Neracionální křivka** je speciální případ racionální křivky, kdy $w_i = 1$. Tvar křivky ovlivňujeme pouze *změnou polohy řídicích bodů*. **Není invariantní** vůči perspektivní projekci.

### Beziérovy křivky

Aproximační **polynomiální křivka** používající *Bernsteinovy polynomy* $B_i^n$.
**Křivka stupně $n$** je určena *$n + 1$ body*.

**Definice křivky**: $$\begin{align}
Q(t) &= \sum_{i = 0}^n P_i \cdot B_i^n(t) \\
B_i^n(t) &= \binom{n}{i} t^i (1 - t)^{n - i}, & t \in \langle 0, 1 \rangle
\end{align}$$

**Rekurentní definice** Bernsteinových polynomů: $$B_i^n(t) = (1 - t) \cdot B_i^{n - 1}(t) + t \cdot B_{i - 1}^{n - 1}(t)$$
