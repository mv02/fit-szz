## Řazení

**Třídění** (*sorting*) položek neuspořádané množiny je *uspořádání do tříd* podle hodnoty daného atributu – *klíče položky*. Mezi třídami *nemusí* být definovaná relace uspořádání.

**Řazení** (*ordering*, *sequencing*) je uspořádání položek podle *relace lineárního uspořádání* nad klíči.

**Setřídění** (*merging*) je vytváření souboru seřazených položek *sjednocením několika souborů* položek téhož typu, které jsou již seřazeny.

> [!note]
> Mezi třídami **nemusí** být definovaná relace uspořádání.
> 
> Pro řazení (*ordering*) se běžně používá nepřesné označení třídění (*sorting*).

### Vlastnosti řadicích algoritmů

**Přirozenost** – algoritmus se chová přirozeně, pokud:

1. doba potřebná k seřazení *náhodně uspořádaného pole* je větší, než k seřazení *již uspořádaného pole* a
2. doba potřebná k seřazení *opačně seřazeného pole* je větší, než k seřazení *náhodně uspořádaného pole*.

**Stabilita** vyjadřuje, zda mechanismus algoritmu zachovává relativní pořadí klíčů se stejnou hodnotou.

> [!example]
> **Nestabilní** algoritmus může uspořádat sekvenci 7, **5'**, 3, 1, **5''**, 9, 2, **5'''**, 8, 4, 6 s výsledkem 1, 2, 3, 4, **5''**, **5'**, **5'''**, 6, 7, 8, 9.
> 
> **Stabilní** algoritmus vytvoří 1, 2, 3, 4, **5'**, **5''**, **5'''**, 6, 7, 8, 9.

## Řadicí algoritmy

### Selection sort

```python
for i in range(0, MAX - 2):
	min_index = i
	min_value = A[i]
	for j in range(i + 1, MAX - 1):
		if min_value > A[j]:
			min_value = A[j]
			min_index = j
	A[i], A[min_index] = A[min_index], A[i]
```

- **Nestabilní**, nechová se přirozeně
- Časová složitost $O(n^2)$

### Bubble sort

```python
n = MAX - 1
cont = True
while cont and n > 0:
	cont = False
	for i in range(0, n - 1):
		if A[i+1] < A[i]:
			A[i+1], A[i] = A[i], A[i+1]
			cont = True
	n -= 1
```

- **Stabilní**, **přirozený**
- Časová složitost $O(n^2)$
- Nejrychlejší metoda v případě, kdy pole je *již seřazené*.

**Odvozené metody** (ripple sort, shaker sort, shuttle sort) jsou obecně rychlejší, ale *ne z pohledu časové složitosti*.

### Insertion sort

```python
for i in range(1, MAX - 1):
	key = A[i]
	j = i - 1
	while j >= 0 and key < A[j]:
		arr[j+1] = arr[j]
		j -= 1
	A[j+1] = key
```

- **Stabilní**, **přirozený**
- Časová složitost $O(n^2)$

### Heap sort

**Hromada** (*heap*) je strom, kde mezi každým rodičovským uzlem a všemi potomky platí *stejná relace uspořádání* (např. rodič je větší než všichni potomci).

**Binární hromada** (*binary heap*) je založena na binárním stromu, pro který navíc platí:

1. všechny hladiny *kromě poslední* jsou **plně obsazené**,
2. *poslední hladina* je **zaplněna zleva**.

Hromada má **v kořeni** vždy *maximální nebo minimální prvek*. Ten může být vložen na své místo do výstupního pole. Vyměníme jej s nejnižším a nejpravějším uzlem. Hromada pak bude **porušena v kořeni**, což napravíme *[[#Rekonstrukce hromady|zatřesením]]*.

```python
# Building the heap
left = MAX // 2 - 1
right = MAX - 1
for i in range(left, 0, -1):
	sift_down(A, i, right)

# Heap sort itself
for right in range(MAX - 1, 1, -1):
	A[0], A[right] = A[right], A[0]
	sift_down(A, 0, right - 1)
```

- **Nestabilní**, nechová se přirozeně
- Časová složitost $O(n\ log\ n)$

#### Rekonstrukce hromady

Jakmile se *poruší pravidlo* hromady v jednom uzlu, probíhá **rekonstrukce** (*zatřesení*, *prosetí*).

Hromadu opraví operace **sift** (prosetí) tak, že *prvek z kořene* postupnými výměnami *propadne na své místo*. V nejhorším případě má operace složitost $log\ n$.

![[30_heap-sort.png]]

- `2 * i + 1 > MAX - 1` → uzel je terminální.
- `2 * i + 1 == MAX - 1` → uzel má jen levého potomka.
- `2 * i + 1 < MAX - 1` → uzel má oba potomky.

```python
# left je kořenový uzel porušující hromadu
# right je index posledního prvku hromady
i = left
j = 2 * i + 1  # Index levého potomka
temp = A[i]
cont = j <= right

while cont:
	if j < right:
		# Uzel má oba potomky
		if A[j] < A[j+1]:
			# Pravý potomek je větší → pokračujeme s ním
			j += 1
	
	if temp >= A[j]:
		# Temp našel své místo → konec
		cont = False
	else:
		# Temp padá níž, A[j] jde o úroveň výš
		A[i] = A[j]
		i = j  # Potomek je v dalším cyklu rodičem
		j = 2 * i + 1
		cont = j <= right

A[i] = temp  # Konečná pozice propadajícího kořene
```

### Quick sort

Pole se **rozdělí na dvě poloviny** (*partition*) – polovina prvků je *menší než medián*, polovina prvků je *větší než medián*. Problém je **nalezení mediánu**, které je *časově náročné*. Proto se používá **pseudomedián**, který svou roli splní velmi podobně jako medián – typicky číslo *ze středu intervalu*.

Postupnou aplikací algoritmu **na každou získanou podmnožinu**, která obsahuje více než 1 prvek, lze získat *seřazenou množinu*.

```python
i, j = partition(A, left, right)
if left < j:
	quick_sort(A, left, j)
if i < right:
	quick_sort(A, i, right)
```

- **Nestabilní**, nechová se přirozeně
- Časová složitost $O(n\ log\ n)$ pro vhodně zvolený pseudomedián, při špatné volbě pseudomediánu $O(n^2)$

#### Mechanismus partition

```python
i = left
j = right
pm = A[(i + j) // 2]

do:
	while A[i] < pm:
		# První A[i] z levé poloviny, které patří do pravé
		i += 1
	while A[j] > pm:
		# První A[j] z pravé poloviny, které patří do levé
		j -= 1
	
	if i <= j:
		A[i], A[j] = A[j], A[i]
		i += 1
		j -= 1
while i <= j  # Konec, když se indexy i, j překříží

return i, j
```

### Shell sort

```python
step = MAX // 2
while step > 0:
	for i in range(step, MAX - 1):
		j = i - step
		while j >= 0 and A[j] > A[j+step]:
			A[j], A[j+step] = A[j+step], A[j]
			j -= step
	step = step // 2
```

- **Nestabilní**, **přirozený**
- Časová složitost $O(n^2)$, existují verze se složitostí $O(n^\frac{3}{2})$ nebo $O(n\ \log^2 n)$

### Merge sort

```python
def merge_sort(A, left, right):
	if (left < right):
		q = (left + right) // 2
		merge_sort(A, left, q)
		merge_sort(A, q+1, right)
		merge(A, left, q, right)

def merge(A, left, mid, right):
	left_count = mid - left + 1
	right_count = right - mid
	
	for i in range(0, left_count - 1):
		# Pomocné pole pro levou posloupnost
		L[i] = A[left+i]
	for j in range(0, right_count - 1):
		# Pomocné pole pro pravou posloupnost
		R[j] = A[mid+1+j]
	
	# Zarážky
	L[left_count] = MAX_INT
	R[right_count] = MAX_INT
	
	i = 0
	j = 0
	
	for k in range(left, right):
		if L[i] <= R[j]:
			# Menší prvek byl v levé posloupnosti
			A[k] = L[i]
			i += 1
		else:
			# Menší prvek byl v pravé posloupnosti
			A[k] = R[j]
			j += 1
```

- **Stabilní**
- Nepracuje in situ
- Časová složitost $O(n\ log\ n)$

## Vyhledávací tabulky

### Sekvenční vyhledávání

```python
def search(t: Table, k: TableKey) -> int:
	found = False
	i = 0
	while not found and (i < len(t)):
		if k = t[i].key:
			found = True
		else:
			i += 1
	return i
```

| Vyhledání    | Čas      |
| ------------ | -------- |
| úspěšné min. | $O(1)$   |
| úspěšné max. | $O(n)$   |
| úspěšně avg. | $O(n/2)$ |
| neúspěšné    | $O(n)$   |

### Sekvenční vyhledávání se zarážkou

**Zarážka** (*sentinel*) dovoluje **vynechat test na konec pole** v každé iteraci. Sníží efektivní kapacitu tabulky o jednu položku, ale algoritmus se zrychlí.

```python
def search(t: Table, k: TableKey) -> bool:
	i = 0
	t[len(t)].key = k
	while k != t[i].key:
		i += 1
	return i != len(t)  # Pokud se došlo az k zarážce, neúspěch
```

### Binární vyhledávání

**Binární vyhledávání** (*binary search*) lze provést **nad seřazenou množinu klíčů** ve struktuře s náhodným přístupem (v poli). Připomíná metodu *půlení intervalu* – je-li hledaný klíč menší než prostředek, pokračuje se v levé polovině, jinak v pravé.

Časová složitost vyhledávání je v nejhorším případě **logaritmická** – $O(\log\ n)$.
Je výhodné pro *statické* tabulky, kde se nemění počet prvků a není nutný potenciálně časově náročný posun segmentu pole.

### Tabulka s rozptýlenými položkami

**Tabulka s rozptýlenými položkami** (*TRP*, *hash table*) využívá **mapovací funkci** – ta musí být *deterministická* a co nejvíce se *vyhýbat kolizím* (rovnoměrné rozložení).

Tabulka se skládá:

- z *mapovacího prostoru* (pole) a
- ze *seznamů synonym* (více klíčů namapovaných do stejného místa).

Seznam synonym začíná na každém prvku mapovacího pole.

Při **explicitním zřetězení** se záznamy v seznamu synonym zřetězují do *lineárního seznamu*. Případně lze použít *vyvažované binární vyhledávací stromy*.

**Implicitní zřetězení** ukládá všechna synonyma *do mapovacího prostoru*, při kolizi postupuje s daným krokem na *první volné místo*.

Vyhledání položky je v nejlepším případě **konstantní** – $O(1)$. Pokud existují synonyma, složitost je **lineární** vzhledem k délce seznamu synonym.

## Vyhledávací stromy

**Kořenový strom** je *[[25. Teorie grafů#Grafy|souvislý acyklický graf]]*, který má *jeden zvláštní uzel* nazývaný **kořen** (*root*). Uzly (vrcholy) bez potomků označujeme jako **listy**, uzly s potomky jako **vnitřní uzly**.

**Seřazený strom** je kořenový strom, ve kterém jsou potomci každého uzlu mezi sebou seřazeni.

**Binární strom** je buď *prázdný*, nebo sestává z *jednoho uzlu zvaného kořen* a *dvou binárních podstromů* – levého a pravého.

Binární strom je **váhově vyvážený**, když pro každý jeho uzel platí, že počty uzlů jeho levého a pravého podstromu se rovnají a nebo se liší právě o 1.

Binární strom je **výškově vyvážený**, když pro každý jeho uzel platí, že výška levého podstromu se rovná výšce pravého podstromu a nebo se liší právě o 1.

### Binární vyhledávací strom (BVS)

**Binární vyhledávací strom** (*binary search tree*) je **binární uspořádaný strom**, pro jehož každý uzel platí:

1. levý podstrom tohoto uzlu je buď *prázdný* nebo obsahuje uzly, jejichž hodnota je *menší než hodnota uzlu*,
2. pravý podstrom tohoto uzlu je buď *prázdný* nebo obsahuje uzly, jejichž hodnota je *větší než hodnota tohoto uzlu*.

Vyhledávání v BVS je podobné binárnímu vyhledávání v seřazeném poli:

1. **Je-li vyhledávaný klíč roven kořeni**, vyhledávání *končí úspěšně*.
2. **Je-li klíč menší**, pokračuje vyhledávání *v levém podstromu*, **je-li větší**, pokračuje *v pravém podstromu*.
3. **Pokud je prohledávaný podstrom prázdný**, vyhledávání končí *neúspěšně*.

#### Rušení uzlu

**Bezdětný uzel** nebo uzel **s jedním potomkem** → *odstranit*, příp. *přepojit sirotka*.

Uzel **se dvěma potomky** → uzel *nechat*, ale **převzít hodnotu** a odstranit:

- *nejpravější uzel levého podstromu*, nebo
- *nejlevější uzel pravého podstromu*.

Takový uzel jde **odstranit snadno** a zároveň se přesunutím *neporuší pravidla BVS*.

### AVL strom

**AVL strom** (podle matematiků *Adělson–Velski–Landis*) je **výškově vyvážený binární vyhledávací strom**, který se *automaticky vyvažuje*.

Jako **kritický uzel** označujeme *nejvzdálenější uzel* od kořene, v němž byla **porušena rovnováha**. *Po porušení rovnováhy* mohou nastat **4 různé situace**:

1. LL – kritický uzel je příliš těžký *vlevo* a jeho levý potomek je těžký *vlevo*,
2. LR – kritický uzel je příliš těžký *vlevo* a jeho levý potomek je těžký *vpravo*,
3. RR – kritický uzel je příliš těžký *vpravo* a jeho pravý potomek je těžký *vpravo*,
4. RL – kritický uzel je příliš těžký *vpravo* a jeho pravý potomek je těžký *vlevo*.

**Situace LL** se opraví *pravou rotací*, **situace RR** *levou rotací*.
Dvojitou rotací se opraví **situace LR** (*levá, pravá*) a **situace RL** (*pravá, levá*).

### (a,b)-strom

**(a,b)-strom** pro parametry $a \geq 2, b \geq 2a - 1$ je obecný vyhledávací strom, pro který navíc platí:

1. kořen má $2$ až $b$ potomků, ostatní vnitřní vrcholy $a$ až $b$ potomků,
2. všechny vnější vrcholy (listy) jsou ve stejné hloubce.
